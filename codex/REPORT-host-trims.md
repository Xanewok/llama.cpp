## Why C grows at np2

The exact C host delta is 0.834 - 0.298 = 0.536 ms/round D from measured phase walls. The C readback delta is 0.031 - 0.006 = 0.025 ms/round D. The supplied function table reports an entire-round fallback `top_k_select` increase of 0.273 ms/round M, not its C-only share. C is submitted by the speculative process hook before target rejection sampling (`server-context.cpp`), and C phase windows run until the next draft launch; therefore target sampling can occupy C's host window. Two slots also double hidden-row handling, KV-trim calls, sampling, and per-slot prompt bookkeeping. `host-attrib.py` reuses the capture segmentation and classifies the recorded host samples by phase to resolve the C-only shares; its results remain pending the CPU gate. It would be incorrect to call the entire delta an MTP forward or graph-build regression.

## Embedding gather and upload choices

`llama-model.cpp:1640` assigns the input layer to CPU regardless of GPU-layer count. Both target and Qwen MTP graphs use `ggml_get_rows` on these weights; quantized rows are dequantized by the CPU backend, then the float rows cross into Meta. CUDA already supports IQ4_XS GET_ROWS (`ggml-cuda/getrows.cu`), and Meta `handle_get_rows` supports mirrored inputs. A mirrored embedding table on both ranks can execute that gather without a new op, but requires a general model-placement policy and extra device memory; relocating just a node would upload the table or fall back. The older report estimates +644 MiB per GPU D for this model's table. Existing tensor-buffer overrides can explore placement separately; GPU/CPU dequantization equality and two-slot VRAM margin need verification before a default change. No embedding-placement change is included here.

`GGML_SCHED_INPUT_STAGING=1` already covers graph INPUT leaves and synchronous host COMPUTE producers, including the CPU GET_ROWS result, with a scheduler lifetime check. Meta requires mirrored transfer destinations and routes the batch to every simple backend. CUDA owns the source bytes in a two-slot pinned ring, uses `cudaMemcpyBatchAsync`, waits for the previous compute before overwriting destinations, and orders compute after the upload event. It already removes per-tensor host synchronizations. There is one upload API batch per active backend split/rank, not necessarily one physical DMA transaction; the scheduler can have multiple splits. Repacking unrelated destinations into one physical copy would require different allocation layout or device scatter and a new lifetime contract. The sampled 0.311 ms/round M host pack is small enough that this is a worse initial gain/risk tradeoff than the index change.

The captures show 14 cudaMemcpyBatchAsync calls/round M at both np1 and np2 (the two ranks across seven decode blocks D), and 19 / 34 H2D activities per device per round M at 8k. H2D activity count is not a tensor count: CUDA can combine a batch's transfers, and other copies share the trace. Per-block H2D sizes/activity counts will be recorded by `host-attrib.py`; the exact per-block scheduler transfer count on a production backend-sampling graph remains a GPU engagement-capture item, rather than being inferred from these API counts.

## Exactness

The position index holds every `(position, physical cell)` for each sequence. `lower_bound({p0, 0})` selects exactly the old scan's membership/range predicate. Advance the iterator before erasing its own entry; deleting that entry cannot invalidate the successor. Every selected cell gets the same `cells.seq_rm` operation. Operations on distinct cells commute; other sequence memberships stay intact. The minimum freed physical index reproduces the old ascending-cell scan's head, including non-monotonic positions and shared cells. Negative sequence removal still uses the old scan. No allocation order or floating-point computation changes.

MTP construction asserts equal target/draft `n_embd_out` and sets target nextn embeddings unmasked. Dense rows are indexed by raw token index. The original process already requires each sequence's batch rows to be contiguous. After the first dense getter synchronizes and reorders target output, catch-up writes only the draft context; shared-memory assistants skip catch-up. Bulk memcpy therefore copies exactly the same bytes that the old per-row getters returned. Later acceptance selects the same row, with the same RNG draws and q/probability computations.
