# MMVQ w2r4 general

Conclusion: regular MMVQ cannot disagree with its host launch geometry; partial rows are safe without extra weight/gate checks in full blocks. sm_120 retains two warps and four rows at five through eight columns. No GPU execution, CUDA application, network, push or queue submission ran. Shape/arch/flag/commit tokens are identifiers; M = measured, D = derived, G = estimate.

Design: `ggml/src/ggml-cuda/mmvq-params.h:176` owns the warp/row constants and full-block division. `mmvq_select_config` selects constants on the host from the existing tables. `mmvq.cu:427` takes them as kernel template arguments, including launch bounds; `mmvq.cu:848` uses the same config for grid/thread dimensions. The kernel no longer selects a device architecture table. Mixed-arch builds or lower-PTX JIT cannot change the encoded geometry independently of the host.

Partial rows: full blocks use floor division. A nonempty remainder gets a separate one-row-per-block launch with the same warp count and a row offset (`mmvq.cu:864`), so nonexistent weight/gate rows are skipped. Full kernels compile out the offset and retain the original K loop without a new bounds check. Irregular shapes pay one extra launch; aligned shapes retain one launch. Bias/store bounds now use true `nrows_x`, separately from destination stride. The legacy split-row caller has no call sites (`rg ggml_cuda_op_mul_mat_vec_q ggml/src`); its shared path nevertheless receives the correct bound. The dedicated multi-token MUL_MAT_ID kernel is unchanged and still needs a separate odd-row safety fix.
