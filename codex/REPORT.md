# Swift verify flash-attention audit

Verdict: GPU correctness remains unverified. Source inspection finds no coupling from unused query columns into real columns in the single-slot verify path. It does establish that crossing query tile width 4 -> 8 changes FP16 accumulation geometry (two -> one parallel warps per column), so numerical equivalence across the boundary is not guaranteed. The mask-scan out-of-bounds concern is real but is gated off there. FP16 value accumulation has a separate finite-range limitation; the parent suite includes an explicit range stress and must not treat a passing q8 staging A/B as proof of general attention correctness.

## Test design

`test_flash_attn_swift_verify` extends the existing FLASH_ATTN_EXT test and is selected only by `LLAMA_TEST_SWIFT_FA=1`. The regular test matrix is unchanged. D: the specialized suite contains 362 cases: 128 base cases, 160 late/constant/large/peak stress cases, 8 combined comparison graphs, 64 served padded-tail cases, and 2 multi-stream mask diagnostics.

Base KV lengths are 4096/4097, 32768/32769, 65536/65537, 102400/102399; query count is 1-8; KV types are q8_0 and f16. Each mask query ends at `used_kv - nb + row`, matching a causal verify suffix. Every graph carries an extra reference-output plane. The combined comparison graphs use exactly the same Q/K/V/mask for batch attention, concatenated one-query attention, and attention over cast-to-f16 KV. At aligned KV, the quantized one-query arm dispatches VEC; at raw non-multiple KV it dispatches generic MMA, explicitly not a VEC comparison.

The oracle compares every individual head/query against a separate F32 CPU attention branch over half-rounded K/V with the existing FLASH_ATTN_EXT NMSE threshold `5e-4`. It also compares the three GPU graph planes against each other and checks constant outputs against represented CPU V. Non-finite tested outputs or F32 CPU oracle outputs fail. The specialized test replaces the generic finite-value comparison because unrelated f16 CPU output can overflow; other tests retain their existing behavior. `LLAMA_TEST_SWIFT_FA_CORRUPT=1` perturbs one output element inside the oracle; the selected normal test must exit with failure. Deterministic integer-generated inputs make boots independent of a random initializer. The suite sets the tested CPU backend to eight threads and uses a single test worker; the CPU reference retains its bounded default. `tests/test-backend-ops.cpp:8032` builds the specialized fixture; `:8072` uses explicit copy destinations; `:8144` computes the independent head oracle; `:9294` selects the opt-in matrix.

## Parent GPU queue

`codex/gpu_ab.sh` is plan mode by default. `CUDA_VISIBLE_DEVICES='' nice -n 19 bash codex/gpu_ab.sh` prints the plan without GPU discovery. Execute only in the parent queue with `RUN_PARENT_GPU=1 PLAN=0 nice -n 19 bash codex/gpu_ab.sh` after the active GPU chain finishes.

The script copies the locally compiled executable as `swift-fa-gpu`, shared libraries, source identity/diff, and queue script to a fresh worktree-local `build-gpu-ab-*` directory and records `SHA256SUMS`. It first verifies the compile-time source/binary manifest, then verifies the frozen manifest before every process. Per GPU it interleaves converted/direct/direct/converted q8 boots of the same bytes. Each boot runs the complete matrix against CPU, including long batch/row/f16 comparisons. It then runs memcheck/racecheck/initcheck/synccheck for each q8 arm on queries 5/6 at short and long KV, and runs the corrupted-output negative control. D: each full boot expects 362 successful cases and each sanitizer run expects 40; skipped/unsupported/empty cases fail. Sanitizer errors/hazards fail. Tests use the CUDA device explicitly, so fallback to another backend cannot silently satisfy the script.

Idle guards inspect both GPU memory/utilization and compute PIDs; clean readable boot kernel logs are required before and after each process. Cleanup stops only the owned timeout PID, which forwards termination to its child; GNU timeout enforces the remaining global budget and a kill grace. Budget is a configurable limit of 7200 seconds, not a runtime estimate. There is no server process or speed benchmark.

## Risks and open work

The first parent run supplies all GPU numerical and sanitizer evidence. A failure in the multi-stream mask diagnostic or range stress must be distinguished from a failure in ordinary single-stream causal cases, but the overall script still fails. Resolve any numerical failure before claiming attention correctness; both q8 arms agreeing can share the same defect.

Passing synthetic operator tests does not certify real Swift logits, long-history reconstruction, CUDA graph replay, recurrent state, input uploads, or exact speculative sampling. MTP verify nb fits within ub=128, so this operator suite does not simulate a 128-query prefill. A later teacher-forced real-model long-prefix test can localize those integration mechanisms after the operator suite.
